# 工程复盘

最难的问题是区分模型选择、工具事实与实际保存结果。早期模型直接选便宜方案，未暴露超预算决策。明确先评估候选后，模型又曾提前停止。修订提示词，要求在允许替换时检查其他候选，并把模型自行停止和已验证全部不可行分别标记，才取得可解释的对照记录。

学习与改进体现在三处。逐次保存评估产物避免失败记录被覆盖；对费用和耗时做程序校验，阻止负费用方案落库；使用真实 SQLite 写入拒绝和 HTTP 协议替身验证异常，而不仅依赖模拟成功路径。Windows 的输出编码和数据库连接关闭问题也在复现中修复。

最终新版真实样例共 15 次，14 次通过，1 次连接失败。此小样本不能代表任意主题或模型都能稳定完成。脚本工具使用合成模板，素材仅两档；费用与耗时为模拟报价。失败结果可导出，但跨进程自动续跑尚未实现。下一步优先扩大独立用例与重复次数，再考虑续跑。

三小时是原计划预算。工作跨 2026-11-04 至 2026-11-05 多轮完成，期间存在等待与中断，无法从提交时间推算有效工时。候选人确认个人累计投入约 2 小时，主要用于需求整理、技术方案协作和多轮迭代沟通。该估计与 AI 自动执行、网络等待的墙钟时间分别记录。
